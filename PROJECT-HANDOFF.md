## Firebase: what exists and where to look

Project ID: `advent-calendar-snowglobe`.

- Web app config: `dist/firebase-config.js`. These browser config fields identify the Firebase app; they are not a server secret.
- Firestore progress logic: `dist/gift-state.js`.
- Firestore Security Rules: `firebase.rules`.
- Authentication uses Firebase **Anonymous** sign-in. Firestore sync needs network access to Firebase’s CDN, Auth, and Firestore. When unavailable or unconfigured, gift state falls back to localStorage.
- Firestore stores only each day’s open timestamp and, where applicable, the letter-open timestamp. Expected location in Firebase Console: select `advent-calendar-snowglobe` → **Firestore Database** → **Data** → collection `giftProgress` → document named `1` through `25`. A document is written only after the matching user interaction; no collection/document is pre-seeded. Gift 3’s envelope adds `letterOpenedAt`.
- In **Authentication** → **Sign-in method**, Anonymous must be enabled. In **Firestore Database** → **Rules**, publish the rules from the project’s `firebase.rules` file. The rules allow anonymous signed-in users to create valid day records once and prevent overwriting progress timestamps.
- The browser’s local progress key currently uses `snowglobe:2026:gifts:v8`. Firestore is authoritative on initialization and snapshot updates: records deleted in Firestore clear their local mirrors instead of being migrated back. Local-to-cloud one-way migration has been removed. To reset progress, delete the day document in Firestore Console; client rules deny deletes, but console admin deletes trigger the listener and clear local status.

### Why Firebase Storage is empty

That is expected with the current code. The `storageBucket` field in `dist/firebase-config.js` only names the configured bucket; the app does not initialize Firebase Storage or upload anything to it. Reaction photos currently live only in the **browser’s IndexedDB** database `snowglobe-reactions-2026`, object store `reactions`, with one record per day (retakes overwrite). They are local to that browser and origin, so they will not appear in Firebase Storage, and another device/browser cannot see them.

To make photos shared, the next implementation must explicitly initialize Firebase Storage, upload each finalised image blob (with a stable path such as `reactions/2026/day-{day}.jpg`), store its download path/URL and metadata in Firestore, and add appropriate Storage Rules. Until those changes are made, Firebase Console → **Storage** will remain empty. Firestore records do not contain the photo itself.
